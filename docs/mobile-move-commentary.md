# 移动端着法讲解与离线朗读

## 使用

- 自由拆棋：当前着法点“讲解这步”，历史着法点旁边“讲解”，候选点“为什么推荐”。
- 录谱回放：底栏“讲解这步”打开分析区域；棋谱列表也支持逐着讲解。
- 训练和 AI 应手：具备题解查看权限时显示讲解入口，题解回放支持逐着讲解。学生受限题目不显示入口，也不生成或朗读答案。
- 讲解提供“局面问题、这步作用、对手应对、后续计划、注意事项”。点击“朗读讲解”才播放，可停止和调整语速。
- 讲解与参考变化使用中文着法，如“炮二平五”，不显示 ICCS 移动坐标。五段以已验证的关键事实为主，省略全盘子力清单和重复说明。
- “后续变化（双方共 N 步）”包含当前这步，每方落子一次计一步；展开后逐步显示行棋方与中文着法。

## 依据与边界

`xiangqi-core::move_facts` 在临时棋盘上调用现有合法落子接口，提取移动棋子、吃子、将军、解将、局面合法吃子机会与子力数量；`moveLineFacts` 经 WASM 返回最多 12 个半回合的事实。事实接口不持有棋谱树或存储句柄。

攻击机会按双方各自行棋的局面快照检查，排除暴露己方将帅的非法吃子。己方走后再次行棋只是检查攻击关系的假设，对手实际仍有应手机会。重复棋例仍以真实棋谱的规则历史判定，不从单个 FEN 推断。

共享讲解模块位于 `packages/move-commentary`。本地 provider 只组织已验证事实与参考线路，不调用大模型。棋谱注释按完整路径绑定，并标为未独立验证的原文。攻击到某子不等于赢子，参考线中吃子不等于强制得子，也不声称读取引擎内部思考。长期战略意图未得到证据支持时明确保留判断。

候选只复用相同走前 FEN、首着匹配的 PV。历史实战着不能用首选代替：没有匹配线路时，分析实际着法之后的局面。没有本地引擎、引擎忙碌或 PV 无法通过校验时保留局面事实并说明原因，允许重试。

## 状态、权限与语音

- 原生引擎由单一协调器管理：AI 应手和训练验证优先，其次常规分析，最后讲解。低优先级讲解不会打断走棋，讲解的取消信号只取消自身任务。
- 切步、切题、换分支、退出、权限或账号作用域变化时取消旧请求和声音，拒绝迟到结果。消费后的历史请求不会在返回旧节点时自动重播。
- 内存缓存最多 100 项，区分局面、目标着法、引擎指纹、搜索参数、棋规、权限作用域、标注和讲解版本。不写 SQLite、不修改棋谱注释或自动保存流程。
- iOS 使用系统 AVSpeechSynthesizer，Android 使用系统 TextToSpeech 的已安装离线普通话声音。缺少语音时提示去系统设置安装；文字始终可用。
- 朗读不采集声音，不需要麦克风、录音或通知授权。Android 的 TTS 服务查询声明不是用户授权申请。以后加入语音提问才需要麦克风权限。
- 朗读停止现有报着音，新落子、退出或进入后台停止讲解语音。Web 浏览器明确提示使用原生 App 朗读，文字功能仍可用。

## 验证

已通过相关 Rust 单元测试、移动端逻辑与 UI 测试、WASM 和移动前端构建、Android Debug APK 构建及原生单元测试、iOS 无签名设备目标构建。

真实 WASM 浏览器回归覆盖手机竖屏、手机横屏和平板，检查红黑历史着法绑定、原棋谱不变、切步清理、返回不重播、录谱讲解面板和水平溢出。

```bash
cargo test -p xiangqi-core -p xiangqi-web-core
pnpm --dir apps/endgame-training test
pnpm --dir apps/endgame-training test:ui
pnpm --dir apps/endgame-training build
# 先启动移动端 Vite；默认地址为 1456 端口，可用 COMMENTARY_URL 覆盖
node scripts/test-mobile-move-commentary-ui.cjs
```

尚需 iPhone、Android 真机验收：飞行模式、普通话语音包缺失/可用、棋子着法发音、系统音量及后台停止。自动化与无签名构建不能替代这些设备验收。

## 习题打开响应

平台练习先显示可操作棋盘，答题历史随后读取；历史返回时核对题目进入代次和账号，切题、返回或账号变化后丢弃旧结果。会话和保存进度仍在显示棋盘前完成恢复。列表点击立即显示可取消的打开提示；棋盘内快速切题仍延迟提示，避免闪烁。

`node scripts/test-mobile-exercise-opening-ui.cjs` 使用真实 App/WASM、合成账号和接口，给历史读取注入 1.2 秒延迟，断言点击反馈在 250 毫秒内、接口返回后棋盘在 600 毫秒内出现。此测试检验客户端是否额外等待，不代表生产服务器或手机上的端到端时延。
