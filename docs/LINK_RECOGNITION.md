# 连线与截图识别

`link-core` 是不依赖图像模型的棋规安全层。视觉 adapter 必须先提交完整
`RecognitionResult`：来源、识别模式、可选四角、透视校正状态、红黑视角、完整
`9 × 10` 交叉点分类、每点置信度和最终 FEN。安全层拒绝缺少交叉点、重复交叉点、
低置信度、缺将帅、棋子超量、跳步和无法唯一推导的局面。

当前桌面端使用随包的 `yolov11.onnx` 和 Rust ONNX Runtime（`ort`）识别棋盘和棋子。
模型来源、SHA-256、输入规格和许可证见
`apps/desktop/src-tauri/resources/link-vision/MODEL-MANIFEST.json` 及同目录的第三方声明。
模型结果是局面观测，不是可直接写入棋谱的走法结论。

## 截图上一着：完整局面优先

天天象棋回放截图中，白色空心圈通常落在走前起点，白色棋子底光圈通常落在走后终点。
两者只能作为视觉证据，不能单独反推出上一着，更不能绕过棋规或覆盖完整局面识别。

导入截图时按以下固定顺序解析：

1. YOLO11 识别完整棋盘、棋子布局和红黑视角，得到截图的走后 FEN。
2. 从当前棋谱节点枚举全部合法一步，并计算每一步走后的棋子布局。
3. 只保留与 YOLO 走后 FEN 的棋子布局完全相同的合法着。
4. 对剩余候选使用白色空心圈和底光圈进行排序；它们只影响顺序，绝不增加候选。
5. 仅当候选唯一时，界面预填“上一着（待确认）”；用户确认后才在当前节点下创建新变例。

因此，若白圈看起来像“炮八退二”，但完整局面一步差唯一对应“马八进七”，界面只能显示
“马八进七”。若完整局面误识别、被遮挡或产生多个合法一步差，界面最多显示三条经过完整
局面校验的候选，让用户选择；没有精确候选时不显示确认按钮。

## 人工回退与棋谱安全

无法唯一确定时，使用标准预览棋盘依次点选起点和终点。系统从**当前棋谱节点**验证该走法，
支持吃子和非吃子；只有合法走法才能成为“待确认”的中文棋谱。红方在下/黑方在下只转换
显示和点选坐标，不交换 FEN、执方或中文记谱。

无论自动匹配、候选选择还是人工点选：

- 用户未确认前不会写 SQLite，不会修改主线或报告。
- 确认后仅在当前节点下新增变例，保留原主线、后续着法和评论。
- 截图无法衔接当前棋谱时，可选择“仅导入独立练习局面”，不会尝试覆盖当前档案。

默认采集策略：

| 来源 | 识别模式 | 最少稳定帧 | 外部点击 |
| --- | --- | ---: | --- |
| `windowLink` / `desktopDetect` | `yoloBoard` | 2 | 可接入 adapter |
| `imageImport` | `yoloBoard` | 1，须用户确认 | 禁止 |
| `cameraBoard` | `perspectiveGrid` | 3 | 禁止 |

## 天天象棋截图验收边界

天天象棋有多种棋盘皮肤、缩放和手机截屏比例。验证样例必须覆盖：红方/黑方视角、木质皮肤、
白色空心起点圈、棋子底光终点圈、缩放、棋子部分遮挡和低置信度。视觉 adapter 只能把中间
棋盘及其 `9 × 10` 交叉点当作候选区域，不得把头像、昵称、等级、计时器、底部导航、河界题字
或特效识别为棋盘或棋子。

`apps/desktop/src-tauri/tests/fixtures/tiantian-black-bottom-board.jpg` 是经人工检查的离线
匿名夹具：只保留棋盘区域，已裁掉状态栏、头像、昵称、战绩、计时、按钮和底部导航。其说明和
SHA-256 在同目录 `README.md`；原始用户截图不得提交、不得在测试日志或构建产物中输出。

该夹具只验证当前已知手机木质皮肤的输入边界。它不能证明所有第三方皮肤、动画、压缩质量或
遮挡都能精确识别。模型无法给出完整、可信的 FEN 时，系统必须进入人工点选或局面校正，而不是
近似猜测上一着。

## 模型与隐私边界

检测到开局动画、局面特效、低置信度格点、棋子数量异常或将帅校验失败时，窗口连线必须保持
`waitingStableFrames` 或 `needsManualCorrection`，不能写入任何着法。动画消失后，只有连续两帧
映射为相同完整局面才允许进入 `tracking`。

个人学习时可在仓库外使用第三方模型，但不得复制模型、原始截图或任何个人资料进入仓库、Git
历史、应用资源、DMG、自动更新资源或同步服务。公开分发必须保留模型许可证、来源、标签映射、
输入规格和 SHA-256，并独立确认训练数据与模型权利；参考项目的 GPL 代码和权重不得在未满足
许可证的情况下混入其他发布渠道。
