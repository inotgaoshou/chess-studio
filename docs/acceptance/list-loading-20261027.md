## 前端改动

- 首页题库请求返回后立即显示题数，不等待独立的棋谱库请求结束。
- 恢复多页题目、教材时，每页到达即显示；后续请求不再挡住首批内容。
- 自动恢复分页期间禁用手动加载更多，保留请求取消、迟到响应隔离和 ID 去重。
- 修正 Node Web Storage 与 jsdom 的测试环境冲突，浏览器测速脚本改为操作真实应用。

验证：17 个测试文件、85 项测试通过；production 前端构建通过。手机尺寸浏览器验证了棋谱请求挂起时首页题数仍显示。专题缓存切换在 Chromium / WebKit 的模拟网络验收中为 31 / 45 ms；这些数值不代表真实线上 API 延迟。

## 服务端改动

对应服务端工作树：`/Users/chenyubin/Documents/xiangqi-admin-private/.local/admin-mate-deps/import-app`。

- 仅对当前目录可能使用的重复题映射执行身份、权限及证据核对，在同一 RR 事务内物化映射，避免候选查询重复展开整套证据关系。
- 先用覆盖索引排除未发布、停用、未就绪的映射端点，再访问原文和核对指纹。生产数据抽样中，537 条具有题目端点的映射只有 7 条同时满足这些基本条件。
- 扩展有限候选窗口至存在重复题映射、或仅筛选杀棋步数的场景；每批结果仍执行完整发布、权限、证据和筛选校验。
- 通过发布状态小索引排除不可用引用，再选择分页窗口，避免多批空的资格校验。保留排序、游标、旧数字游标兼容与原题 ID。
- 新增幂等迁移 `0070_catalog_reference_cover.sql`，覆盖 `content_record_classifications(asset_id,asset_version_id,source_index,mate_moves)`。

## 已在线生效的改动

仅覆盖索引已应用到正式 MySQL，使用 `ALGORITHM=INPLACE, LOCK=NONE`，DDL 锁等待上限为 5 秒；执行过程中没有备份、没有修改业务数据、没有重启服务。
