# 实用残局读取失败与服务端响应优化

## 复现

已安装 iPhone / iPad App 的“实用残局”读取失败。直接访问正式教学题库接口也复现：目录结构约 1.8 秒返回，但题目列表 45 秒无响应；客户端 15 秒超时会先显示读取失败。

可重复验收命令：`python3 scripts/check-practical-endgames.py --credentials <审核账号文件> --deadline 1 --output <结果文件>`。脚本使用正常登录，验证目录、统计、20 题首屏、20 题下一页及 ID 不重复；不输出账号、密码、令牌或题目内容。基线结果保存在 `.local/practical-endgames-before.json`。

## 已确认原因

- 全库教学统计使用一个巨大的证明与引用关联 SELECT，正式环境出现持续约 24 分钟的执行。
- 统计版本滞后，使列表不能使用当前有序投影，反复回退到实时校验。
- 数据库竞争期间交换空间接近耗尽，HTTPS 与 SSH 曾间歇超时。14:22 的内核日志确认 MySQL 被全机 OOM 终止并自动重启；不是人工重启数据库。
- 暂停该派生查询后，第一轮候选代码在服务器本机的重复分页仍需约 1.2–1.8 秒，尚不能作为 1 秒验收结果。

## 修复范围

服务端工作目录：`/Users/chenyubin/Documents/qixi-topic-status-fix`，基于当前正式版本 `db510bf`。

- 合入此前已验证、尚未上线的目录候选窗口与限定范围的重复题映射优化。
- 将全库题目证明校验与引用映射拆成有限批次，保持同一个可重复读事务，在全部完成后发布完整派生快照。
- 排序统计复用限定范围的重复题映射，避免全库反复展开身份和证据校验。
- 统计独占连接的单条 SELECT 上限为 10 秒，失败后等待 30 秒再重试。
- 限制统计连接的优化器搜索深度；教材资格校验也按实际目录引用分批执行。
- 统计使用禁用预编译语句缓存的专用连接。批次包含不同 ID，保留这些查询的 MySQL 解析树没有复用收益；杀法步数查询也显式禁用缓存，并在批次间让出执行时间。
- 集成测试逐次比较新旧统计集合和排序引用，保留撤回、证据变化、权限、分页和重复题的原有语义。
- 统计规则与格式保持兼容。没有修改客户端请求超时。

## 性能证据范围

每组 18 次请求：三轮根目录、目录结构、统计、20 题首屏、20 题下一页，再做三个并发读取。断言首/次页各 20 个不重复 ID。

| 环境 | 请求数 | 最慢 | 结果 |
| --- | ---: | ---: | --- |
| 统计修复后，原正式服务，本机 HTTP | 18 | 930.54 ms | 全部 < 1 秒 |
| R7 只读预览，本机 HTTP | 18 | 354.45 ms | 全部 < 1 秒 |
| 原正式服务，经正式域名 HTTPS，由服务器发起 | 18 | 479.79 ms | 全部 < 1 秒 |
| R7 正式服务，经正式域名 HTTPS，由服务器发起 | 18 | 863.79 ms | 全部 < 1 秒 |

原服务的教材/复现补充检查中有两个首次请求为 1.25 / 1.44 秒，后续为约 0.21–0.44 秒；不能据此声称所有接口永远 < 1 秒。R7 正式发布后的 12 次教材/复现请求最慢 984.03 ms，32 次目录/具体书籍请求最慢 749.59 ms，全部 < 1 秒，实际数量断言通过。

开发 Mac 上正式域名被本机代理 DNS 解析为 `198.18.0.39`，HTTPS 握手失败；禁用请求代理并指定真实 IP 也发生 TLS 超时。服务器发起的正式 HTTPS 验证正常。没有改动用户网络配置，也没有把服务器发起的请求声称为 iPhone 蜂窝网络实测。

原始证据保存在本机 `.local/practical-server-acceptance.jsonl`、`.local/practical-server-r7-acceptance.jsonl`、`.local/practical-server-https-acceptance.jsonl`、`.local/practical-book-production-check.jsonl` 和 `.local/practical-material-acceptance.jsonl`；均不包含登录凭证或令牌。
