# 阶段性循环学习打卡

## 使用入口

- 学生：手机首页“今日打卡”，或“作业”中的“学习打卡计划”。
- 老师：手机老师工作台“学习打卡”。电脑后台有同名入口。
- 两个孩子：在现有班级中添加两个学生账号，使用老师账号分别建立计划。布置范围选“指定学生”，哥哥计划只勾选哥哥，妹妹计划只勾选妹妹。两个孩子各自登录，任务、照片、进度及徽章分别保存。也支持整班统一布置。

填写阶段名称、北京时间起止时分和一周任务模板。每项任务可指定科目、要求、执行星期、必做／选做、照片必交／可选。发布预览显示实际日期、短周及任务数量；每天至少有一项必做任务。发布后接收名单固定；日常调整可直接编辑原计划，下一阶段可复制为新草稿。

## 完成与补充

每项提交成功后盖“成”字印章；当天全部必做任务完成，小马前进一步。选做任务可盖章但不影响当天达标。完整自然周获得“七日坚持”，首尾短周按实际安排天数获得“阶段周完成”。每周独立计算，漏一天不会清除其他成果。

未要求照片时可以直接确认完成，心得可选。印章表示已完成并提交，不代表作业全部正确。老师可查看照片、留言或填写原因退回。退回会重算当天和周成果，已有徽章标注“需补充”；重新提交后恢复原徽章。

阶段开始前只可查看，不能提前提交未来日期。阶段结束后七天内可补交，归属原任务日期，并显示实际提交时间。补交截止后封存，停止提交、重交和退回，保留历史与老师留言。

草稿、照片和待同步记录保存到 IndexedDB，按服务地址、学生账号与机构隔离。上传失败保留本机数据，联网后重试；正式印章与徽章以服务端接收成功为准。已封存或发生版本冲突的请求保留并显示失败原因，不无限重试。页面默认无声音，可关闭动效，并遵守系统减少动态效果设置。

## 接入与维护

手机教学服务与电脑后台位于相邻的 `xiangqi-admin-private` 仓库，新增迁移 `0050_learning_checkins.sql` 和 `/api/v1/checkin/*`、学生提交／照片、老师管理／审核接口。此功能独立于象棋习题和评分。发布事务一次生成所有每日任务快照，提交 UUID 幂等，revision 防止旧请求覆盖退回结果。

共享 UI 的源文件位于 `apps/endgame-training/src`，通过以下脚本同步到后台前端：

```bash
node tools/sync-checkin-ui.mjs
node tools/sync-checkin-ui.mjs --check
```

后台升级需包含迁移 0050、服务端和后台前端；手机需使用包含新页面的构建并连接已升级的教学服务。仅更新手机端不能提供新接口。最初开发验证时尚未部署、未生成安装包；当前测试上线状态见下文。

## 2026-10-20 原计划编辑、复制与删除

日常调整优先使用“编辑计划”，保留同一计划编号，不产生第二份阶段。选择北京时间生效日期（不早于今天和开始日）并填写修改原因；名称、结束时间及周任务模板可修改。生效日期之前的任务，以及已经有提交、照片、审核或幂等动作记录的任务保留原要求和编号。已发布计划的开始时间与接收名单固定，已封存计划只可复制。修改后的未记录任务使用新编号，旧设备的离线提交不能误完成新要求；失败的本机记录继续保留。

“复制新阶段”只打开草稿，默认从原计划及同一学生可见计划的最晚结束日之后开始，阶段天数保持原值；已结束很久时从今天开始。班级成员也参与默认日期计算。服务端按发布时实际接收名单与北京时间日期检查重叠，覆盖指定学生和整班布置；补交期不算任务日期重叠。机构锁串行化并发发布与日期变更，两个冲突计划不能同时发布。已有重叠允许在原日期范围内修订，新增覆盖日期必须通过检查。

“删除”需要界面确认，使用软删除：学生和老师列表、打卡统计中不再展示，停止提交、照片上传、审核及详情访问，数据库中已有打卡、照片与审核记录保留。重复删除幂等，不自动转移或合并两份计划的提交记录；当前未提供回收站页面。

后端迁移为 `xiangqi-admin-private/migrations/0054_checkin_plan_management.sql`，增加计划 revision 与变更审计。PUT 保留原草稿 JSON 字段，新增 expectedRevision、effectiveDate、reason；已发布计划要求版本号及修改原因，旧草稿客户端仍兼容。DELETE 使用 expectedRevision 与 reason。编辑与删除均检查原有机构、老师权限；已删除的 create/publish 重试不能恢复计划。上线需先更新后端迁移和服务，再更新后台及手机前端。本轮仅本地实现验证，现有诗涵/弘平计划未修改，未部署或重新打包原生安装包。
