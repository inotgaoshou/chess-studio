# 杀法步数筛选与紧凑分支入口

基线：手机/桌面仓库 `26f1f5b1`；后台 authoring-release 工作树 `b1d0fcf`。

## 用户需求

1. 教师“选择题库／书本”弹窗增加杀法步数筛选，且与搜索、分页组合使用。
2. 单条“继续”应明确为棋谱已有的下一着，与 AI 极速出招区分；默认在引擎下方或棋盘外，可以拖动、收起。
3. 多分支仅显示编号与着法按钮，删除大标题和重复副标题；默认稍下方，不遮棋盘，仍可拖动。
4. 延续六按钮单行和分支不占排版空间、不改变棋盘大小的行为。

## 实现

- 共用教师创作组件增加“一步杀、两步杀、三步杀、四步及以上、全部步数”。进入书本后沿用步数筛选，返回保留条件；筛选变化重置分页并忽略旧结果。棋谱库不显示杀法筛选。
- `/authoring/source-libraries` 与 `/authoring/sources` 共同支持 mateMoves/mateGroup。平台题按当前来源、局面和内容指纹仍有效的强制杀验证筛选；机构自建题使用已验证发布版本的杀棋目标步数。筛选在分页前执行，不用书名数字或答案长度推断。
- 服务端返回 `mateFilterVersion:1`；旧服务端不会被当成已筛选成功，界面明确提示更新后重试。
- 浮层单条按钮改为“下一着：着法”，操作只是进入已有节点。AI 最优走法仍由“极速出招”操作。
- 浮层多条仅保留编号、着法、小型拖动/管理/收起控件；单条也可收起并恢复。编号与原箭头、分支顺序一致。
- 默认在棋盘外的引擎内容下方；录谱优先使用棋盘与工具栏之间至少 52px 的空隙，否则在现有状态提示行的左侧保留区悬浮，不覆盖右侧讲解按钮或改变工具栏高度。拖动、旋转后仍限制在棋盘外可用区域，保留用户请求的位置。
- 没有改动分支存储、主线或原生命令。共用教师组件已同步至后台工作树。

浏览器使用隔离数据与模拟业务接口，服务端通过一次性本地 MySQL 验证；均不操作正式数据。
