# 做题多解与皮卡鱼复核

本次改动覆盖桌面残局、手机本地导入、平台练习和老师作业；双方复现模式仍按原谱演示。

## 判题与续走

- 共享判定代码位于 `crates/training-verifier`，服务端、Tauri 与移动 WASM 使用相同规则。React 只接收结构化证据，不解析 UCI。
- 合法的标注外走法进入“皮卡鱼复核中”。只有明确不达标才记错；超时、引擎故障、目标不全、深度不足或上下界分数返回“待复核”。
- 杀棋采用有预算的全部合法防守搜索。PV 仅用于排序，不作为强制杀证明；超过规定步数或有有效防守时不通过。
- 非杀棋要求明确结构化目标，默认比较深度 26、最大损失 50 cp、验证范围 12 半回合。最低净子力收益或最低解题方评估分由内容审核人工确认。
- 子力表：车 1000、马炮 500、士象 200、兵卒 100；比较相对起始局面的净收益，并沿引擎最佳应对检查回吃。
- 正确的新路线返回真实应手和提示。原题解耗尽不代表完成；完成必须满足实际目标。
- 标注存在明显矛盾时进入审核。缺少目标条件的旧题仍可按原题解练习，额外走法待复核。

## 离线与版本

本机有皮卡鱼时可离线验证。平台本地通过显示“待服务端复核”，联网后按本地尝试顺序幂等补交；老师作业仍需学生手动提交。

新路线、续走证据和平台会话草稿保存在本机；恢复时重新校验证据。账号、机构、服务器、题库版本和内容条件隔离缓存；切题、重来和退出使旧响应失效。手机私有题路线仅存在本机，不加入平台补交队列。

缓存键包含完整路径、候选着、内容目标、判定版本、引擎/NNUE 指纹与搜索配置。单次验证限时 15 秒，搜索与全部防守证明有独立预算。

## 后端与上线

配套仓库 `xiangqi-admin-private` 新增通用 `verify-move`，保留 `mate-move` 兼容接口。成绩与作业提交重新验证，不信任客户端通过状态，使用作业/练习快照。

上线需包含管理后台迁移 `0053_answer_verification.sql`。新增答案复核列表区分漏收解法、标注疑似错误及目标条件缺失；修正生成版本与审计记录，并冻结已有作业快照，经原有审核流程重新发布。后台人工目标编辑器可补充验证条件。

构建后端时需同时取得配套 chess-studio 共享 Rust crate，沿用仓库现有相对路径依赖布局。移动发布前需重建 WASM，并同步 Capacitor 前端资源。此次未部署、未签名发布或提交应用商店。
