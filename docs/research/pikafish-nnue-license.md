# Pikafish 与 NNUE 权重的商业使用边界

> 记录日期：2026-07-30。本文是基于官方发行包和官网的工程许可梳理，不构成法律意见；商业发布前应取得权利人的书面确认，并由法务复核。

## 结论

不能简单地说“Pikafish 不能商用”。官方发行包中的**引擎程序**采用 GPLv3，官方说明明确包含销售或作为更大软件包的一部分销售的情形；但本项目当前使用的官方 `pikafish.nnue` 是**单独许可的权重文件**，其许可证写明未经许可不得商业使用。因此，使用“Pikafish 引擎 + 官方 `pikafish.nnue`”的商业产品，须先取得权重的商业授权（或确认自己在官方授权名单内）。

## 分开判断的对象

| 对象 | 官方许可/条件 | 对本项目的含义 |
| --- | --- | --- |
| Pikafish 引擎源码与二进制 | GPLv3 | 可商业使用、销售和分发；若向用户分发引擎二进制，须随附 GPL 许可证及生成该确切二进制的对应源码或其有效获取方式。修改引擎源码时，修改也应以 GPLv3 提供。 |
| 官方 `pikafish.nnue` 及其派生权重 | `NNUE-License.md` | 使用即同意许可；仅限合法用途，未经许可不得商业使用。官网授权名单所列个人和组织获准商业使用。 |

依据：官方 README 将发行包中的 `.nnue` 文件与 GPLv3 的 `Copying.txt` 分别列为不同文件，并在 GPL 条款部分说明引擎的分发义务。[README：47-62、110-126](../../../Pikafish.2026-01-02/README.md)；[NNUE 许可：7-15](../../../Pikafish.2026-01-02/NNUE-License.md)。

## 两种交付方式

### 1. 桌面应用本地捆绑

若 DMG、安装包或首次下载内容向用户提供 Pikafish 二进制，属于引擎的分发：应保留 GPLv3 许可证，并提供与所分发二进制对应的源码或准确源码地址。仅因 GPLv3 并不禁止收费，但其中的官方 `pikafish.nnue` 仍需要独立的商业许可，不能因为引擎可商业分发而自动获得权重商用权。

依据：[README：114-126](../../../Pikafish.2026-01-02/README.md)；[GPLv3：34-38、195-206、245-291](../../../Pikafish.2026-01-02/Copying.txt)。

### 2. 服务端远程分析

GPLv3 规定，在服务器上运行程序、用户仅通过网络交互且没有收到程序副本，不属于“convey”（分发）。因此纯服务端运行通常不触发 GPLv3 针对二进制分发的对应源码提供义务。Pikafish 使用的是 GPLv3 而不是 AGPLv3。

但权重许可证使用的是“Any usage”和“No commercial use without permission”的表述；服务端实际加载官方 `pikafish.nnue` 仍然是对该权重的使用，不能仅靠“不下发二进制”规避其商业使用限制。

依据：[GPLv3：92-101](../../../Pikafish.2026-01-02/Copying.txt)；[NNUE 许可：7-13](../../../Pikafish.2026-01-02/NNUE-License.md)。

## 授权名单与可选路径

官方 NNUE 许可将商业许可指向 [Pikafish 授权列表](https://pikafish.org/list.html)。该页面区分“软件授权列表”和“远程引擎授权”，并显示部分同意公开的名单；产品名称未在该页出现时，不应推定已经获授权。

可执行的发布选择：

1. 从 Pikafish 权利人取得与桌面捆绑、远程分析、收费模式相匹配的书面授权，并确认可使用的具体权重版本。
2. 更换为已确认可商用且与所选引擎兼容的权重，并单独核验其来源、许可证和再分发条件。
3. 发布非商业版本时仍遵守 GPLv3 的引擎分发义务、NNUE 的合法使用条件，以及任何第三方素材许可。

官方 NNUE 文件还说明：Fairy-Stockfish 的中国象棋变体训练权重采用 CC0，尽管训练数据和过程相关，仍不受该 Pikafish 权重许可约束；这只是官方给出的例外描述，不等于所有第三方权重均可直接替换或商用。[NNUE 许可：15](../../../Pikafish.2026-01-02/NNUE-License.md)。
