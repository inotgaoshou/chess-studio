# 棋研 1.2.3 中文使用手册

本手册面向使用棋研复盘比赛棋谱的孩子与家长，重点说明整局复盘、U10 引导拆棋、棋理解释和开局训练。推荐主流程是：

> 导入或手动录谱 → 保存归档 → 生成整局报告 → U10 引导拆棋 → 棋理解释 → 保存变例 → 间隔复练

## 工作模式

顶部工作模式默认是`复盘`，适合按上面的闭环完成一盘比赛棋。`研究`用于实时引擎、开局库、飞刀、大师棋谱和分支推演；其中引擎、登录、网络和系统权限的前置条件会直接显示。`训练`用于任务、U10 拆棋、间隔复习和学习档案，和复盘共用同一盘棋与报告；关闭 U10 拆棋后会回到训练上下文。

`研究实验`中的窗口连线在 macOS 依赖屏幕录制和辅助功能权限，属于实验功能。Windows 10 1903+ / Windows 11 可在`窗口连线`中选择一个可见的 Chrome 或 Edge 天天象棋网页窗口；应用只处理该窗口的客户区画面，不保存网页截图。Windows 只支持观战跟盘和用户逐步确认走子：点击`确认走子`后，程序会先再次核对局面、窗口位置、客户区尺寸和 DPI，再自动点击起点和终点；不提供自动代走。浏览器最小化、关闭、失焦、移动、缩放、管理员权限不一致或未识别棋盘时会安全暂停或拒绝过期点击，等待新的稳定识别帧后才能再次确认。该能力尚需在真机 Chrome/Edge 的 100% 与 125% 缩放下验收，未验收前仍标为“实验”。Web 版只提供离线棋谱、基础变例和待同步操作，不提供桌面本地引擎、报告 PDF、训练或连线。

## 1. 首次准备

### 检查本地引擎

1. 打开 `人机对弈 → 引擎设置`。
2. 主引擎选择内置 Pikafish，或选择你已配置的外部 Pikafish。
3. 建议先使用 `候选走法 3`。整局首轮可使用深度 20–22，关键节点再提高到 22–26。
4. 线程和 Hash 按电脑性能设置；一般使用 2–8 线程、256–1024 MB Hash。
5. 点击`检测并保存`。只有检测成功后，局面分析和整局报告才有可靠结果。

持续分析适合研究当前局面；整局报告仍需在复盘工作台中由用户主动生成，不会因为导入棋谱自动占用引擎。

### 准备开局数据

当前 1.2.3 发行包暂不附带内嵌学习开局库或棋理资料包，以控制 macOS 与 Windows 安装包体积；相关源资料保留在开发环境，后续会以按需下载/安装方式提供。开局训练可先使用本地导入的 XQB、ElephantEye 或 ChessDB 候选，并由 Pikafish 核对局面。

- `ChessDB 云开局库`需要网络，会发送当前 FEN 查询候选着法。
- `棋局 → 导入 XQB 开局库`可加入本地 XQB 数据；具体内容由所导入文件决定。
- `棋局 → 导入 ElephantEye 开局库`可加入本地 ElephantEye 学习库。
- 网络或外部开局库不可用时，不影响本地棋谱与 Pikafish。

### 保存方式

棋研采用“应用内主库 + Finder 单向镜像”的保存方式：合法落子、评论、变例、飞刀标注、整局报告、训练和归档资料先自动保存到本机 SQLite 主库。复盘中的`保存归档`确认文件夹、收藏和标签；归档后的棋谱会自动生成或更新 Finder 中的完整 PGN 镜像。

本机数据库位于：

`~/Library/Application Support/cn.xiangqi.studio/xiangqi.sqlite3`

Finder 默认镜像目录：

`~/Documents/棋研棋谱/`

镜像按`年份/赛事/日期_赛事_对手_执方.pgn`分层。完整 PGN 保留主线、变例、用户评论和飞刀标注，适合 Finder 查看、手工备份和分享；整局报告、训练成绩和学习总结仍只保存在 SQLite。

`保存棋谱/另存为 PGN`仍由你主动选择任意外部位置，不会改变自动镜像路径。Finder 中打开或编辑过的 PGN 必须按“导入新棋局”处理，不能反向覆盖原棋局，以免覆盖应用内的新变例和训练资料。

需要备份时，先完全退出棋研，再复制该文件。恢复前也应退出应用，并先备份当前数据库。Finder 路径不会参与跨设备同步。

## 2. 整局复盘

### 建立一盘棋

顶部切换到`整局复盘`。空棋谱时有三个入口：

1. `导入棋谱`：选择已有 PGN。
2. `一键录入`：从剪贴板识别局面或文本棋谱。
3. `手动录谱`：从标准初始局面逐步走棋。

手动新建棋局预设到`比赛复盘`，但没有录入合法着法前仍显示`待录谱`。导入棋谱默认未分类，便于你确认资料后再归档。

### 归档与报告

录入后点击`编辑归档`，填写文件夹和标签，按需点亮收藏，再点击`保存归档`。选择文件夹或收藏只改变草稿，不点击保存不会写入 SQLite。

归档完成后点击`生成整局报告`。报告与当前棋谱线路、引擎版本、深度、线程和 Hash 绑定。棋谱结构发生变化后，旧报告显示`需重新分析`，旧评分、趋势和关键问题不会冒充当前结果。

复盘洞察包含四页：

| 页签 | 用途 |
| --- | --- |
| 整局报告 | 红黑综合质量、阶段表现、复盘建议和 PDF |
| 局势趋势 | 观察优劣变化和关键转折点 |
| 关键着法 | 按红黑方查看问题着、推荐着与解说 |
| 训练 | 从当前有效报告生成关键或巩固任务 |

点击完整棋谱、关键着法或较早节点只是导航棋盘，**不会删除后面的着法**。只有明确执行`删除分支`才会删除数据；从旧节点走出新着时，原后续应保留为分支。

## 3. U10 引导拆棋

### 从正确局面开始

生成整局报告后，进入`关键着法`，选择一个问题着法并点击`U10 拆棋`。系统从问题着法**之前**的局面开始，让孩子重新决定，而不是在错误已经发生之后补救。

### 第一阶段：先独立思考

提交前，系统隐藏引擎箭头、候选线和局面分。孩子需要完成：

1. 对方有什么直接威胁。
2. 是否有将军、吃子、捉双等强制手段。
3. 己方最差的子是哪一个。
4. 列出 2–3 个候选着。
5. 选择首选着，并推演 4–8 个半回合。

可以在小棋盘上依次点击起点和终点录入临时线路。临时线路只属于本次拆棋：不写 SQLite、不修改真实棋谱树，也不会生成真实变例。`撤回一步`只撤回临时推演；关闭未提交题目会取消本次会话。

家长只按界面中的`家长提问`继续追问，例如“如果让对方连续走两步，他最强的反击是什么？”，不要提前评价答案或打开引擎提示。

![U10 拆棋：提交前](/manual/03-u10-before.png)
*图 3：①答案隐藏；②临时推演棋盘；③威胁与强制着检查；④候选着和预测线路；⑤家长只提问。*

### 第二阶段：提交后核对

点击`提交并揭示答案`后，Pikafish 才显示 MultiPV、中文线路、定性局面评价和棋理卡。结果分为：

- `计算正确`：首选和主要反击均命中。
- `方向正确`：候选合理，但次序或计算不完整。
- `漏算反击`：没有发现对方的强制手段。
- `原则问题`：与已确认棋理卡存在可靠匹配。

`100 cp = 1.00 局面分`只用于引擎核对；孩子学习时优先理解`均势、稍优、明显优势、胜势`。合适的临时线路可点`保存为普通变例`，保存后才进入真实棋谱。

普通强招不等于飞刀。只有另行验证出明确诱导条件，且对方按诱导应手后达到至少 +1.00 分或形成可靠杀势，才继续设计飞刀。

## 4. 棋理学习

研究模式右侧进入`棋理库`，可查看`本地棋理库`。当前发行包不预装棋理资料包；后续安装的原创 U10 原则卡将覆盖开局协调、王安全、强制着扫描、候选着、线路控制、兑子、残局转化、时间管理和赛场纪律。

每张卡应结合以下内容学习：

- `适用局面`：什么时候应该想到这条原则。
- `判断问题`：落子前需要回答什么。
- `常见错误`：孩子通常漏掉什么。
- `反例`：什么时候不能机械套用。
- `证据`：当前局面的棋子、威胁或引擎线路如何支持结论。

只有同时具备局面事实或引擎证据时，界面才把它作为当前结论；只有阶段或标签相似时，显示为`参考原则`。参考原则是检查清单，不是正确答案。

外部书籍、课程或本机资料生成的原则卡保持`待审核`，必须由用户确认后才参与棋谱思路。误匹配时应提交反馈，系统会降低该卡在相似局面中的权重。完整 PDF、OCR 和长文本不随安装包分发。

## 5. 开局训练

### 一本库解决“大家怎么走”，引擎解决“这个局面好不好”

开局训练先看已导入本地库或 ChessDB 的常见候选，再用 Pikafish 验证。开局库的次数、胜率或排序表示实战数据，**不是红黑局面分**；局面优劣只采用当前 Pikafish 的评分和线路。

推荐步骤：

1. 在标准初始局面开始走自己的常用体系。
2. 每个分支点记录库中最常见的 2–3 个应手。
3. 分别用 Pikafish 检查自己的主应对和对方最佳防守。
4. 把常见偏离保存为普通变例，并写一句“为什么这样应对”。
5. 对红方、黑方分别复练，不把一方经验直接套到另一方。

### 个人红黑布局画像

打开 U10 训练的`学习档案`可查看`最近比赛布局画像`。系统只读取最近 20 盘已经归档的比赛棋谱，并分别统计执红和执黑；同一体系至少出现 3 次才进入个人常用布局。

样本不足时会明确提示使用内置专题，不会把一两盘偶然对局说成个人弱点。建议棋谱标签保持稳定，例如`省赛、执黑、中炮、屏风马`。

## 6. 日常训练方法

U10 训练窗口包含`引导拆棋、今日 40 分钟、家长周报、学习档案`四页。每次建议严格控制在 40 分钟：

| 时间 | 内容 | 方法 |
| --- | --- | --- |
| 5 分钟 | 间隔复习 | 完成今天到期的 1/3/7 天复测 |
| 15 分钟 | 个人实战拆棋 | 从自己的比赛关键着法独立计算 |
| 10 分钟 | 同类专题 | 练习相同薄弱标签或布局偏离 |
| 5 分钟 | 残局 | 练习兑子、兵卒和优势转化 |
| 5 分钟 | 总结 | 孩子说出漏算原因，家长记录一句话 |

题目默认来自个人比赛棋谱 60%、内置专题 40%。复习按 1、3、7 天安排；同一任务三次复测达到 80 分以上，且最近两次没有使用提示，才标为`已掌握`。

12 周安排：

1. 第 1–2 周：基线诊断和计算习惯。
2. 第 3–5 周：强制着、候选着和反击检查。
3. 第 6–8 周：个人红黑布局体系及常见偏离。
4. 第 9–10 周：优势转化、兑子与残局。
5. 第 11 周：限时比赛模拟。
6. 第 12 周：同类局面复测和阶段总结。

家长在`家长周报`查看本周作答数、平均分、无提示完成率、已掌握任务、薄弱标签和下周重点。不要只比较总分，应优先观察漏算反击是否减少、候选着是否完整、提示依赖是否下降。

## 7. 常见问题

下面的排查不会删除棋谱、变例、评论或飞刀方案。遇到问题时，先确认当前棋局、报告状态和顶部状态提示，再按对应项目处理。

| 现象 | 先检查 | 处理结果 |
| --- | --- | --- |
| 没有关键着法 | 报告是否完成且有效 | 无明显失误时改生成巩固训练，不会人为制造错题 |
| 没有红黑布局画像 | 已归档比赛棋谱数量与执棋方 | 样本不足时改用内置专题，不给出虚假的个人结论 |
| 报告显示需重新分析 | 是否改过主线、变例或引擎设置 | 重跑当前报告，旧分值不再作为当前结论 |
| 引擎无结果 | Pikafish、局面合法性和运行中的任务 | 修复配置后重新分析，原棋谱仍会保留 |
| 训练任务为空 | 当前报告是否有效、是否已生成过同节点任务 | 优先关键失误，再回退巩固训练，已完成任务不会被覆盖 |

### 报告显示“需重新分析”或过期

报告绑定生成时的棋谱线路和引擎参数。主线、变例、注释相关的线路变化，或深度、线程、Hash、引擎版本变化后，旧报告会标为`需重新分析`。

1. 在`整局复盘 → 复盘洞察`查看状态。
2. 点击`重新生成报告`，等待当前棋谱的分析完成。
3. 重新生成前，不要把旧报告的评分、趋势、关键着法或 PDF 当作当前棋谱结论。

旧报告不会覆盖棋谱本身；重新分析只更新报告数据。

### 报告没有关键着法

先确认报告已完成且没有过期。当前深度下没有明显失误并不等于没有训练价值；`训练`页会尝试从 30–79 cp 的次优着中生成最多 3 个`巩固训练`。

仍为空时，表示当前有效报告没有满足阈值的节点。可以选择比赛中自己犹豫的局面，在研究模式做自由推演或手动保存普通变例；不要把它标成系统识别的 U10 错题。

### U10 拆棋按钮没有出现

先完成有效的整局报告，再到`关键着法`选择一个问题节点。没有报告问题的节点仍可自由推演，但不会伪装成系统识别的 U10 错题。

### 没有红黑布局画像

布局画像只读取最近 20 盘、已归档为比赛棋谱的对局，并分别统计执红和执黑。同侧、同一体系至少出现 3 盘才会形成个人画像；不足时按内置开局专题训练即可。

导入后请在复盘工作台点击`编辑归档`，确认文件夹、标签后点击`保存归档`。建议持续使用稳定标签，例如`省赛`、`执黑`、`中炮`、`屏风马`。样本不足是正常保护逻辑，不代表导入失败。

### 引擎没有结果

1. 打开`人机对弈 → 引擎设置`，确认主引擎为内置或已选择的 Pikafish。
2. 点击`检测并保存`；检测失败时重新选择外部引擎路径，或切换回内置引擎。
3. 检查当前 FEN 或手动摆出的局面是否缺将帅、存在重叠棋子或不符合棋规。
4. 报告生成中、人机正在思考或棋谱播放中时，先停止该任务，再重新请求分析。

引擎暂时无结果不会删除本地棋谱，也不会自动替换已有变例。请查看顶部状态提示或按钮悬停说明中的具体失败原因。

### 训练任务为空或没有新增任务

训练任务必须来自当前棋局的有效报告。系统先选择分值变化达到 `80 cp` 的关键失误；没有此类节点时，选择 `30–79 cp` 的次优着生成最多 3 条巩固训练。

- 报告过期时先重新生成报告，不能从旧报告创建任务。
- 同一份报告、同一个节点已经存在的任务会去重，避免重复练习；已完成状态不会被新生成动作覆盖。
- 如果仍显示没有可训练节点，说明本局在当前分析深度下没有合适题目。可先完成到期复习，或在下一盘比赛报告中继续生成。

### 自动保存、归档、Finder 镜像与另存 PGN 有什么区别

- SQLite 是唯一可编辑主库：合法落子、评论、变例、报告、训练、飞刀和归档资料都先保存到这里。
- `保存归档`确认文件夹、收藏和标签；已归档且至少有一着合法走子时，系统会自动创建或更新 Finder 的完整 PGN 镜像。
- 自动镜像默认在`~/Documents/棋研棋谱/年份/赛事/`；镜像状态显示为`已镜像、待创建、写入失败或已暂停`。在左侧棋谱资料可点`更新镜像`、`Finder 显示`和`镜像设置`。
- `保存棋谱`和`另存为 PGN`是你主动选择的额外文件，不会改变自动镜像路径。手动导出失败不影响 SQLite 内的自动保存内容。
- 自动镜像只从 SQLite 导出到 Finder；不要在 Finder 编辑镜像后期待自动回写。需要使用外部修改时，按`导入棋谱`创建新棋局，再在应用内继续编辑。
- 镜像根目录是本机偏好，不参与账号同步，避免另一台设备出现无效 Finder 路径。

### 自动镜像没有创建、更新失败或文件被删除

1. 先在当前棋谱左侧确认它已完成`保存归档`且至少有一着合法走子；空白草稿和未分类导入棋谱会显示`待创建`。
2. 点击`更新镜像`。若显示`写入失败`，检查 Finder 目录是否被删除、磁盘是否可写，或在`镜像设置`中选择一个有写入权限的目录后重试。
3. 文件名相同的不同棋局会自动追加短棋局 ID，不会覆盖别盘棋；日期、赛事、对手或执方资料变化后，系统会移动并重命名旧镜像，不保留旧副本。
4. 如果在 Finder 手动删除了镜像，点击`更新镜像`即可从 SQLite 重新创建。若要一次重建所有已归档棋谱，进入`镜像设置 → 重新生成全部`。

镜像失败不影响棋谱自动保存、报告、训练或飞刀。先修复目录后再更新即可。

### 如何备份和恢复本机数据

数据库位置为：

`~/Library/Application Support/cn.xiangqi.studio/xiangqi.sqlite3`

备份步骤：完全退出棋研，确认 Dock 中应用已不再运行，再复制 `xiangqi.sqlite3` 到自己管理的备份目录。运行中的 SQLite 可能同时使用日志文件，因此不要在应用运行时只复制主数据库文件。

恢复步骤：先完全退出棋研，把当前 `xiangqi.sqlite3` 复制一份作为恢复前备份，再用需要恢复的备份文件替换该路径下的 `xiangqi.sqlite3`，最后启动棋研。恢复的是棋谱、归档、报告、训练和本机学习数据；Finder 自动镜像和手动另存 PGN 都不会自动还原。恢复数据库后可在`镜像设置 → 重新生成全部`重建归档棋谱的镜像。

### 云库、同步和窗口连线不可用

| 功能 | 前置条件 | 未满足时的行为 |
| --- | --- | --- |
| ChessDB 云开局库 | 网络；查询会发送当前 FEN | 可继续用本地 XQB、ElephantEye 和 Pikafish，本地棋谱不变 |
| 云同步 | 网络和已登录账号 | 仅暂停同步，本机 SQLite 仍可正常保存和使用 |
| 窗口连线 | macOS 需要“屏幕录制”；Windows 需要 Windows 10 1903+ 或 Windows 11、可见未最小化的 Chrome/Edge 天天象棋网页窗口 | 不采集外部画面，不向棋谱写入识别结果；Windows 可改用截图/照片导入 |
| 确认走子/自动对战 | 先有稳定连线；macOS 需要“辅助功能”；Windows 要求棋研和浏览器以相同管理员权限运行，且确认前后的窗口位置、尺寸、DPI 必须与识别帧一致 | 不执行鼠标点击；Windows 不提供自动对战，只能逐步确认走子；窗口移动或缩放后自动重标定，期间拒绝过期点击 |

首次授权后可在 macOS`系统设置 → 隐私与安全性`中查看或撤销权限。网络失败、未登录、未授权或识别不稳定时，应用应停止外部动作并保留本机棋谱。

### 其他导出方式

- `保存棋谱`更新当前外部棋谱文件。
- `另存为 PGN`由你选择 Finder 位置。
- 分享与导出还可生成棋谱 PDF、复盘报告 PDF、GIF 或变招图 SVG。

遇到按钮无反应时，先看顶部状态提示和按钮悬停说明；权限、网络、账号或引擎条件不足时，应用会保持本地棋谱不变。
